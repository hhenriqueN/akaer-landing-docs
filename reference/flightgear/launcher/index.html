    Launcher do FlightGear¶

    Dois launchers equivalentes (mesmos argumentos e env vars):

    • macOS: scripts/launch_flightgear.sh (bash). Usado pelo console via console/flightgear.py e para rodar direto do terminal.
    • Windows: scripts/launch_flightgear.ps1 (PowerShell) para o terminal; o console no Windows chama o fgfs.exe direto a partir de console/flightgear.py (sem shell).

    Ambos iniciam o simulador na pista 02 de BIKF e conectam o protocolo UDP.

    Uso¶

    # macOS
bash scripts/launch_flightgear.sh                  # calmo
bash scripts/launch_flightgear.sh 270 10           # vento cruzado 10 kt de 270°
bash scripts/launch_flightgear.sh 270 12 0.3       # idem + turbulência 0.3

    # Windows
.\scripts\launch_flightgear.ps1                    # calmo
.\scripts\launch_flightgear.ps1 270 10             # vento cruzado 10 kt de 270°
.\scripts\launch_flightgear.ps1 270 12 0.3         # idem + turbulência 0.3

    No bash, argumentos extras após o terceiro são passados ao FlightGear. No PowerShell, use $env:FG_APP/$env:FG_ROOT para apontar binários específicos.

    Variáveis de ambiente¶

    Variável Padrão Para quê
    FG_APP macOS: detectado em /Applications, ~/Applications, DMG montado. Windows: fgfs.exe em C:\Program Files\FlightGear*\bin\ Caminho para o .app/fgfs.exe
    FG_ROOT macOS: ~/Library/Application Support/FlightGear/fgdata_2024_1. Windows: <install>\data Pasta de dados do FlightGear
    FG_SCENERY vazio Caminho extra de scenery (--fg-scenery=); útil no Windows
    LAT / LON 63.937617 / -22.605467 Posição inicial (graus)
    HEADING 0.02 Proa inicial (°)
    ALT_FT 801 Altitude inicial (ft)
    SPEED_KT 82 Velocidade inicial (kt indicados)
    TIME_OF_DAY noon noon, dawn, dusk, midnight, real
    GUST_KT vazio Rajada em kt; se setado, vira --wind=FROM@KT:GUST
    VISIBILITY_M vazio Visibilidade em metros; se setado, adiciona --visibility=…
    MANUAL vazio Se 1, adiciona --generic=…console_manual_cmd em UDP 5504 e FGReplay contínuo (voo manual)

    Essas env vars são o canal pelo qual o console de voo empurra o cenário escolhido para o FG (vento + rajada + visibilidade + hora + condição inicial). Rodar o launcher pelo shell continua funcionando por argumentos posicionais (wind_from wind_kt turbulence).

    O que o launcher faz¶

    1. Resolve FG_APP (monta ~/Downloads/flightgear-2024.1.7-macos-universal.dmg se precisar).
    2. Copia config/flightgear/pfe_{out,in}.xml para $FG_ROOT/Protocol/.
    3. Executa:
    FlightGear \
  --aircraft=c172p \
  --lat=63.937617 --lon=-22.605467 --altitude=801 --heading=0.02 --vc=82 \
  --timeofday=noon --disable-real-weather-fetch --disable-ai-traffic \
  --wind=<from>@<kt> --turbulence=<norm> \
  --prop:/controls/flight/elevator-trim=-0.03 \
  --prop:/sim/rendering/shaders/quality-level=1 \
  --generic=socket,out,60,127.0.0.1,5501,udp,pfe_out \
  --generic=socket,in,30,127.0.0.1,5502,udp,pfe_in \
  --telnet=5401

    Suporte de SO¶

    • macOS: scripts/launch_flightgear.sh + console/flightgear.py (que chama o shell). Comportamento intocado desde a v1.
    • Windows: scripts/launch_flightgear.ps1 (terminal) e console/flightgear.py que executa fgfs.exe direto via subprocess.Popen (console). Mesmos XMLs, mesmas env vars, mesmo UDP.
    • Linux: não suportado — PR bem-vinda. O caminho mais barato é adaptar o scripts/launch_flightgear.sh para localizar o fgfs do seu gerenciador de pacotes e manter o resto igual.
