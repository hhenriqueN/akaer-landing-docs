    Abrir o console de voo¶

    O console local é uma página de navegador para escolher um controlador treinado e vê-lo controlar o FlightGear em tempo real. Faz tudo o que scripts/run_flight.sh faz, mas sem terminal.

    macOS e Windows

    O launcher do FlightGear funciona nos dois: no macOS roda scripts/launch_flightgear.sh, no Windows chama fgfs.exe direto a partir do console/flightgear.py. Em Linux o botão FLY aparece desabilitado. Ver Launcher do FlightGear.

    Em um comando¶

    python -m console.server

    O terminal imprime o endereço:

    Console aberto em http://127.0.0.1:8770  (Ctrl+C para fechar)
Telemetria UDP em 127.0.0.1:5503

    Abra o link no navegador. O console só aceita conexões de 127.0.0.1.

    Fluxo¶

    1. Escolha um controlador na página inicial (os cartões ficam cinza se faltar peso).
    2. Opcional: escolha um cenário fixado na faixa superior ou abra + cenários para editar/criar um.
    3. Clique FLY. O console:
      1. inicia o console.runner, que importa o piloto escolhido e abre UDP 5501;
      2. aguarda ~3 s e lança o FlightGear via scripts/launch_flightgear.sh, passando o cenário por env vars;
      3. começa a receber telemetria pela porta UDP 5503 e abre os instrumentos.
    4. Durante o voo: ADI, HSI, fitas de IAS/ALT, VSI, manche, mapa top-down da pista com as trajetórias dos voos-piloto em cinza e barras de comando.
    5. Clique PARAR (ou feche o navegador) para encerrar o runner. O log é salvo em artifacts/flights/, como em scripts/run_flight.sh.
    6. Feche o FlightGear à mão — o launcher não derruba o simulador, por desenho.

    Cenários¶

    O editor de cenários (+ cenários na página inicial, ou ⚙ num cenário fixado) permite salvar presets de vento, rajada, turbulência, visibilidade, hora do dia e condição inicial (distância, altura, desvio lateral, proa, velocidade). Cada preset vira um JSON em console/scenarios/<id>.json e aparece como "chip" na faixa superior quando fixado (📌). Presets travados (🔒) são imutáveis — use ⧉ para duplicar e editar uma cópia.

    As condições adversas do preset são todas propagadas para o FlightGear via env vars do launcher (ver Launcher do FlightGear).

    Voo manual¶

    O cartão VOO MANUAL inicia um voo em que o autopilot não envia nada: você pilota o C172P via teclado ou joystick, usando o cenário selecionado. O FG grava um CSV compatível em artifacts/flights/, útil para coletar demonstrações novas no mesmo cenário em que os modelos rodam.

    Bateria de testes¶

    ABRIR BATERIA permite rodar o produto cartesiano N modelos × M cenários × R repetições em ordem intercalada (voo após voo, com reinício do FG entre eles). O estado da execução vai para artifacts/baterias/<nome>/estado.json; os CSVs continuam em artifacts/flights/. O painel de progresso mostra os voos concluídos ao vivo via SSE. Útil para comparar modelos sob cenários controlados sem precisar reiniciar o console a cada voo.

    Temas¶

    Quatro temas no dropdown do canto superior direito: AKAER (vinho sobre branco, padrão), WINE, AMBER, PHOSPHOR (fundo escuro estilo MFD). Clique na estrela para fixar um tema como principal (abre nele na próxima vez). A escolha fica em localStorage.

    Portas e tokens¶

    Porta Direção O que trafega
    8770 (HTTP) navegador ↔ console páginas, JSON, SSE
    5501 (UDP) FlightGear → runner 60 Hz de telemetria do simulador
    5502 (UDP) runner → FlightGear 10 Hz de comandos
    5503 (UDP) runner → console (features, cmd) espelhados pelo runner

    Cada execução gera um X-Console-Token novo. Toda ação (/api/fly/start, /api/fly/stop) exige o token no cabeçalho — o HTML já o injeta. Qualquer requisição com Host fora de 127.0.0.1:8770/localhost:8770 é rejeitada.

    Arquivos relacionados¶

    • Trilhas dos voos-piloto: cache em console/cache/piloto_tracks.json (gerado na primeira requisição a /api/piloto). Invalidado por mtime/size dos CSVs em Data/csv/voos-piloto/.
    • Log do FlightGear: artifacts/flightgear.log (stdout/stderr do simulador).
    • Logs de voo: artifacts/flights/<run_name>_<timestamp>.csv + .json.

    Variáveis úteis¶

    Mesmas de Voar no FlightGear: FG_APP, FG_ROOT. Opcional: console/local.json pode sobrescrever http_port, udp_telemetry_port e os caminhos do FlightGear por máquina (ver console/local.json.example).
