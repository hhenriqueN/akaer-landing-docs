    IAS — 14 tiny cascading ANNs¶

    Port of the Intelligent Autopilot System from Baomar & Bentley 2021 into this repository, based on the code at Tanakavitor/plane (Vitor Tanaka, team member). Unlike the other models, this one is not PyTorch: each ANN is a 1-hidden-layer MLP, tanh, 5–10 neurons, pure NumPy.

    • Code: src/ias/ (library), src/ann_ias.py (training), src/fly_ias.py (flight).
    • Issue: #24.

    What is different¶

    Item MLP-5 / GRU IAS
    Architecture 1 net per command (aileron, elevator, ...) 1 ANN per physical task (track → roll, desired_rate → elevator, ...)
    Net ~15 K params, one large hidden layer 5–10 neurons, pure tanh, no bias on the lateral channels
    Persistence binary .pt human-readable JSON (artifacts/ias/ias_models.json)
    Memory fixed lags / GRU hidden state leaky integrals (τ=30 s for centreline, τ=10 s for heading on ground)
    Phase no explicit phase flight manager FINAL → FLARE → LANDING
    Set-points constants in the code median of the demonstrations (glideslope, aim-point, flare height)

    The 14 ANNs¶

    15 in the paper. We skip brakes because the current pipeline does not preserve brake_left/brake_right. The controller uses a ground-speed fallback (clip((gs−10)/50, 0, 1)).

    Phase FINAL (10 ANNs)¶

    Longitudinal cascade:

    ANN hidden input(s) output
    glideslope_roc 5 glideslope angle error [°] desired sink rate [ft/s]
    glideslope_elevator 8 (desired − actual) sink rate [ft/s], IAS [kt] elevator
    throttle 5 desired sink rate [ft/s] throttle
    flaps 10 AGL [ft], IAS [kt] flaps (quantized 0, 1/3, 2/3, 1)

    Lateral cascade (odd — no bias, anti-symmetric output):

    ANN hidden input(s) output
    track 8 centreline angle [°], leaky integral [°·s] desired track [°]
    roll 5 (desired − actual) track [°] desired roll [°]
    aileron 8 (desired − actual) roll [°], current rudder aileron
    rudder 5 heading error [°] rudder

    Phase FLARE (2 ANNs + reuse)¶

    ANN hidden input(s) output
    flare_roc 5 AGL [ft] desired sink rate [ft/s]
    flare_elevator 8 (desired − actual) sink rate [ft/s], IAS [kt] elevator
    flare_throttle 5 AGL [ft] throttle

    FINAL lateral ANNs (track, roll, aileron, rudder) stay active.

    Phase LANDING (3 ANNs + brake heuristic)¶

    ANN hidden input(s) output
    heading 5 centreline angle [°] desired heading [°]
    rudder_ground 8 (desired − actual) heading [°], leaky integral [°·s] rudder
    landing_elevator 5 ground speed [kt] elevator (keep attitude in roll-out)

    Brake: clip((gs_kt − 10) / 50, 0, 1) (heuristic, not an ANN).

    Data pipeline¶

    src/ias/data.py loads eligible episodes from Data/processed/full_episodes/ (segmentation already done by pipeline v3), drops INITIALIZATION_TRANSIENT to keep FG startup lat/lon from poisoning the aim-point estimate, and runs each flight through the IAS FeatureExtractor (first-order low-pass filters, internal leaky integrals, CG height = 3.5 ft). Output in Data/processed/ias/.

    Set-points are estimated from the median of the flights (see estimate_aim_point in data.py):

    Set-point Current value Source
    aim-point past threshold 341 m median of altitude × along-track fits
    glideslope 5.3° median of fits
    flare height 52 ft median AGL at first touchdown
    v_ref 70 kt median IAS at touchdown

    The 5.3° glideslope is steeper than the 3° manual default: it reflects this repo's demonstrations, not the paper's.

    Training¶

    • Loss: MSE on targets scaled to [−0.9, 0.9] (tanh never saturates).
    • Optimizer: gradient descent with momentum, lr=0.1, momentum=0.9 (eqs. 1–3 of the paper).
    • Epochs: 150. Batch: 32.
    • Probe + deployed: the script trains each ANN twice — a probe on the train-only split (to measure held-out MSE) and a deployed model on all demonstrations (for flight). Only the deployed model is written to ias_models.json.
    • Held-out: voo-2-com-16-nos (same fixed_diagnostic_holdout.yaml as the rest of the repo).
    • Noise floor: for each ANN, the irreducible MSE is estimated by binning the inputs into 25 cells per dimension and taking the variance of the target within each bin.
    • Lateral symmetry: track, roll, aileron, rudder, heading, rudder_ground train with no bias and with symmetric scalers (lo = -hi), and data is duplicated by mirroring. Result: f(-x) = -f(x) exactly. Zero error → zero command, by construction.

    Commands:

    python src/ann_ias.py                 # full run (rebuilds Data/processed/ias/)
python src/ann_ias.py --skip-build    # train reusing existing Data/processed/ias/
python src/ann_ias.py --epochs 50     # fast iteration loop

    Outputs in artifacts/ias/: ias_models.json, 02_training.md, 02_ann_fits.png, 02_learning_curves.png.

    Closed-loop flight¶

    src/fly_ias.py hooks IntelligentAutopilot into the FlightGear UDP loop at 10 Hz (zero-order hold decimating from 60 Hz). Unlike fly_4.py or fly_rnn.py, it does not use normalization.json or the pipeline features.py: the IAS has its own causal FeatureExtractor (inside src/ias/), and IntelligentAutopilot.step(obs) accepts the raw FG dict (lat, lon, AGL, roll, pitch, heading, IAS, ...) and returns {aileron, elevator, rudder, throttle, flaps, brake} in FlightGearLink format.

    bash scripts/run_flight.sh                 # default nets (MLP-5)
CONTROLLER=ias bash scripts/run_flight.sh  # IAS
CONTROLLER=ias bash scripts/run_flight.sh 270 10   # 10 kt crosswind from 270°

    Logs in artifacts/flights/ias_<timestamp>.csv, same columns as fly_4.py (along-track, cross-track, phase, airspeed, vs, cmds), so comparison against other models still holds.

    Persistence¶

    artifacts/ias/ias_models.json layout:

    {
  "params": { "aim_x_m": 341.37, "glideslope_ref_deg": 5.30, "flare_height_ft": 52.1, ... },
  "models": {
    "track": {
      "W1": [[...]], "b1": [[...]], "W2": [[...]], "b2": [[...]],
      "in_lo": [...], "in_hi": [...], "out_lo": [...], "out_hi": [...],
      "odd": true,
      "meta": { "phase": "final_approach", "mse": 0.043, "n_samples": 38314, ... }
    },
    ...
  }
}

    JSON because it is small (~70 KB, all 14 ANNs combined) and auditable. Loaded by src/ias/ann.py:load_models.

    Known limits¶

    • No brakes ANN: the pipeline does not preserve per-wheel brake inputs. The ground-speed fallback stops the aircraft but does not reproduce the demonstrated brake schedule.
    • No vn_fps/ve_fps: FeatureExtractor falls back to heading as a proxy for track. Adequate up to 16 kt wind, degrades under strong crabbing.
    • No go-around: the flight manager only moves FINAL → FLARE → LANDING, no return.
    • Specific to C172P/BIKF 02: set-points and scalers are measured from the flights — swapping aircraft or runway requires retraining.

    Console¶

    Registered as family="ias" in console/models.py. console/model_info.py reads the JSON and emits one "component" per ANN in the card (name, phase, number of neurons, MSE, n_samples), instead of a PyTorch block.

    When to revisit¶

    • Pipeline starts preserving brake_left/brake_right: unlock the brakes ANN by removing the skip in src/ann_ias.py.
    • Sampling rate changes: review DT in src/ias/config.py (τ of filters and integrals depends on it).
    • vn_fps/ve_fps added to the pipeline: wire track = atan2(ve, vn) into FeatureExtractor (today it falls back to heading).
    • Train/val/test split changes: retrain everything — set-points are measured on the same demonstrations that train the ANNs.
